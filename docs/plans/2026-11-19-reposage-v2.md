# RepoSage v2 Implementation Plan

**Goal:** Ship RepoSage v2 (chunked retrieval, three agent ADK pipeline, Issue to Fix Plan, Verified Citations, Trace, limits) on Cloud Run.

**Architecture:** FastAPI holds one in memory FAISS index of Chunks. A Google ADK Researcher gathers Evidence through tools; a Writer and Reviewer loop produces an Answer or Fix Plan with Verified Citations. See `docs/TRD.md`.

**Tech Stack:** Python 3.12, FastAPI, google-adk, google-genai, faiss-cpu, pytest.

**Spec:** `docs/PRD.md`, `docs/TRD.md`, `GLOSSARY.md`, `docs/adr/`.

## Global Constraints

- Follow `CLAUDE.md` hard rules: no AI attribution, one commit per task, push after each task, branch `v2-agents` only.
- Tests never touch the network. Use `tests/fakes.py`.
- Use the Glossary's words in UI copy and identifiers (Chunk, Evidence, Citation, Fix Plan, Trace).

## Review Focus

1. Citation line numbers off by one between `chunker`, `read_lines` and GitHub links (test in Tasks 1 and 5).
2. ADK instruction text containing literal braces gets treated as state templates (test in Task 4: build agents and render instructions).
3. Reviewer never calls `exit_loop` and the loop runs twice every time (test in Task 4 with a FakeLlm that approves on the first pass: assert one Writer call).
4. Issue URL from a different repository than the one indexed (test in Task 6: expect 409).
5. Model output rendered as HTML in the frontend (Task 8: render with `textContent` only).

## Tasks

### Task 1: Retrieval core (chunker, embeddings, vector store)

**Files:** `backend/chunker.py`, `backend/embeddings.py`, `backend/vector_store.py` (drafted), create `backend/tests/fakes.py`, `backend/tests/test_chunker.py`, `backend/tests/test_vector_store.py`, `backend/requirements.txt`, create `backend/requirements-dev.txt`, `backend/requirements-local.txt`, `backend/pytest.ini` (`pythonpath = .`).

**Interfaces:** as in TRD Modules table. `FakeEmbedder` has `embed_documents(list[str]) -> np.ndarray` and `embed_query(str) -> np.ndarray`, 64 dims.

1. requirements: replace `sentence-transformers` and `google-generativeai` with `google-adk`, `google-genai`, `numpy`, `httpx`; move `sentence-transformers` to `requirements-local.txt`; dev: `pytest`, `httpx`.
2. Tests: a 3 function Python file yields 3 Chunks with symbols and correct 1 based lines (decorators included); a 200 line `.md` yields windows starting at lines 1, 46, 91, 136, 181; a syntax error `.py` falls back to windows; `RepoIndex.search` ranks the chunk sharing the query's tokens first and drops results below `min_score`; `read_lines` clamps ranges and returns `None` for unknown paths.
3. Check: `python -m pytest -q` passes.
4. Commit: `feat(retrieval): chunk files and index chunks with faiss cosine search`.

### Task 2: Simple mode on the new store

**Files:** `backend/rag_pipeline.py`, `backend/citations.py`, tests.

1. `citations.py`: `parse_citations(text) -> list[tuple[str,int,int]]`, `github_url(repo_url, path, start, end) -> str`, `resolve(text, index, repo_url) -> list[dict]` (keeps paths present in the index).
2. `rag_pipeline.answer_question(question) -> (answer, citations, trace)` using `vector_store.current().search`, prompt asks for `path:start-end` after every claim; one `google.genai` call; generation isolated in `generate(prompt) -> (text, usage)` so tests monkeypatch it. Model `gemini-2.5-flash`.
3. Tests: citation regex, URL format `#L10-L24`, simple mode with monkeypatched `generate`.
4. Commit: `feat(simple): answer with line level citations from chunk retrieval`.

### Task 4: ADK pipeline and Trace

**Files:** `backend/agent/pipeline.py`, `backend/tests/fakes.py` (add `FakeLlm`), tests.

**Interfaces:** `async run(question: str, issue: dict | None = None, llm=None) -> dict` returning `{answer, trace}`; `build_root(llm) -> SequentialAgent`.

1. Researcher, Writer, Reviewer per TRD Agents table; `LoopAgent(max_iterations=2)`; model from `llm` param (FakeLlm in tests) else `gemini-2.5-flash`.
2. Run with `InMemoryRunner`, new session per request; walk events to build Trace (agent author, function calls, usage tokens); final answer is session state `draft`.
3. Tests with FakeLlm: Reviewer approves first pass gives exactly one Writer call; Reviewer rejects then approves gives two; Trace counts tool calls and sums tokens; no literal braces break instruction rendering.
4. Commit: `feat(agent): run researcher, writer and reviewer loop with trace`.

### Task 5: Issue to Fix Plan

**Files:** `backend/issues.py`, `backend/agent/pipeline.py` (issue mode instructions), tests.

1. `parse_issue_url(url) -> (owner, name, number)`; `fetch_issue(url) -> {title, body, url}` via `httpx` to `https://api.github.com/repos/{owner}/{name}/issues/{n}`, 10 s timeout, body truncated to 4,000 characters.
2. Issue mode: Researcher gets issue title and body; Writer produces a Fix Plan with sections Files to change, Steps, Tests to update, Risks; each item cited.
3. Tests: URL parsing (valid, pull request URL rejected, other host rejected); pipeline with FakeLlm in issue mode.
4. Commit: `feat(issues): turn a github issue into a cited fix plan`.
